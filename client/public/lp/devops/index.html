Detailed syllabus · 8 phases · 4 months

From beginner to DevOps engineer, one phase at a time

Networking & Linux give you the foundation every server runs on; Git and build tools package your code; Docker containerizes it; CI/CD and Kubernetes ship and orchestrate it; Terraform and Ansible provision and configure the infrastructure underneath; and AWS & observability keep it running in production. By the Capstone, every earlier skill comes together in one project.

1Phase 1Networking & Linux FundamentalsEvery DevOps engineer needs a rock-solid grip on how machines talk to each other, and how Linux actually works underneath. This phase builds both from zero.
Networking Basics · Linux FundamentalsNetworkingDNSLinuxEC2
  • How the Internet works, DNS resolution
  • OSI & TCP/IP models, TCP vs UDP
  • IP addressing, subnetting, ports & protocols
  • EC2 server setup, SSH & key management
  • Linux kernel, shell & filesystem hierarchy
  • File types, links, I/O redirection, pipes, env vars
What you'll be able to do after Phase 1

By the end of this phase, every student can set up and SSH into a real EC2 Linux server, and understands exactly how requests travel across a network — the foundation every later phase builds on.

Where this shows up on the job

Every production incident starts with “can we SSH into the box?” — this is the phase that teaches you to set up, secure and troubleshoot that server before touching any higher-level tool.

2Phase 2Advanced Linux & GitFrom basic commands to real system administration, alongside the version control every engineering team runs on.
Advanced Linux · GitLinux AdminShell ScriptingGitGitHub
  • User/group management, permissions & ACL
  • File searching & text processing utilities
  • Package management, archives, job scheduling & LVM
  • Git fundamentals, workflow & branching
  • Merging, conflict resolution & undoing changes
  • Remote repositories & GitHub collaboration
What you'll be able to do after Phase 2

By the end of this phase, every student can administer a real Linux server end to end and manage code with the same Git workflows professional engineering teams use daily.

Where this shows up on the job

Every CI/CD pipeline and every production server comes back to these two skills — a DevOps engineer who can't administer Linux or manage Git branches confidently can't do the job.

Try it yourself

Write a shell script that archives a folder, then push it to a new GitHub repo using a proper branch and a clean commit message.

3Phase 3Build Tools & DockerFrom compiling code across every major language ecosystem to packaging an entire application into a container.
Build Tools · DockerMavennpmDockerAmazon ECR
  • Maven & Gradle for Java projects
  • npm for Node.js, pip for Python
  • Dockerfile, multi-stage builds & Compose
  • Docker architecture, images & containers
  • Networking, volumes & Amazon ECR
  • Docker Swarm, YAML basics & debugging
What you'll be able to do after Phase 3

By the end of this phase, every student has containerized a real multi-service application end to end — from a Dockerfile to a Docker Compose stack pushed to Amazon ECR.

Where this shows up on the job

“It works on my machine” stops being a problem the moment an app is containerized — this is the exact skill every job posting means by “Docker experience”.

Try it yourself

Write a Dockerfile for any small app you've built, build the image locally, and push it to a free Amazon ECR repository.

4Phase 4CI/CD & Kubernetes FoundationsMoving from containers on your laptop to containers that build, test, ship and orchestrate themselves.
CI/CD (Jenkins + GitLab) · Kubernetes + Helm Part 1JenkinsGitLab CI/CDKuberneteskubectl
  • Jenkins install, architecture & Freestyle jobs
  • Jenkins pipelines, Jenkinsfile & integrations
  • GitLab CI/CD & GitLab Runners
  • KIND & kubeadm cluster setup
  • Kubernetes architecture & kubectl
  • Pods, ReplicaSets, Deployments & Services
What you'll be able to do after Phase 4

By the end of this phase, every student has built a real CI/CD pipeline, then deployed their first application onto a Kubernetes cluster they set up themselves.

Where this shows up on the job

This is the exact workflow behind every “push to deploy” setup — a Jenkins or GitLab pipeline that tests, builds and ships your app onto Kubernetes automatically, every time you commit.

Try it yourself

Write a Jenkinsfile that builds a Docker image and deploys it to a local Kubernetes cluster with a single pipeline run.

5Phase 5Advanced Kubernetes & DevSecOpsProduction-grade Kubernetes, plus the security layer every modern CI/CD pipeline is expected to have built in.
Kubernetes + Helm Part 2 · DevSecOpsHelmEKSSonarQubeTrivy

What you'll be able to do after Phase 5

By the end of this phase, every student can deploy a production-grade application on AWS EKS with automated security scanning built directly into the pipeline.

Where this shows up on the job

Modern hiring teams expect security scanning inside the pipeline, not bolted on afterward — this phase is what lets you say “DevSecOps” on a resume and back it up in an interview.

6Phase 6Terraform & AnsibleThe two pillars of modern DevOps: provisioning cloud infrastructure as code, then configuring it automatically.
Terraform · AnsibleTerraformHCLAnsibleAnsible Vault

  • Ansible architecture & inventory management

  • Variables, facts, handlers, loops, tags, roles & Ansible Vault
What you'll be able to do after Phase 6

By the end of this phase, every student can provision real AWS infrastructure with a few lines of code, then configure it automatically — the exact skillset behind every “infrastructure as code” job listing.

Where this shows up on the job

Spinning up a server by hand in the AWS console doesn't scale past a handful of machines — Terraform and Ansible are how real teams provision and configure hundreds of servers identically, every time.

Try it yourself

Write a Terraform script that provisions a free-tier EC2 instance, then an Ansible playbook that installs and configures a web server on it.

By the end of this phase, every student is fluent across the core AWS services real job postings ask for, with a full observability stack monitoring everything they've built.

Where this shows up on the job

A deployment that isn't monitored is a production incident waiting to happen — Prometheus, Grafana and Loki are the exact stack behind the alerts and dashboards every on-call DevOps engineer relies on.

FAQ

Common questions

Do I need a coding or IT background?

No. The course starts from networking and Linux fundamentals, and mentors guide you phase by phase.

How long is the course, and how are classes held?

4 months of live classes, 5 days a week, across 8 phases. Every session is recorded and available 24/7, so you can catch up if you miss one.

Will I work on real servers and AWS?

Yes. You set up EC2 servers, deploy to EKS, and provision infrastructure with Terraform on real AWS accounts, using AWS's free credits and free tiers.

Do I need to buy any software?

No. Terraform, Ansible and Jenkins are open-source, Docker Hub and GitHub Actions have free tiers, and AWS gives free credits to new accounts. Provider limits can change.

Is a job guaranteed?

No institute can honestly guarantee a job. Every student gets placement support: resume and profile building, mock interviews and job referrals. Offers depend on your performance and the hiring company.

What is the fee, and is EMI available?

Your counselor will share the current fee, any scholarship you qualify for, and the payment options on your free call.
